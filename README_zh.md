## 框架简介

现代SAT求解器已经经过了极其精细的优化，人类专家想要获得进一步的显著性能提升变得愈发困难。AESAT 是一个新颖的神经符号（Neuro-Symbolic）框架，旨在利用大语言模型（LLMs）自动进化和优化SAT求解器的启发式函数。

它采用了一种受模因学（Memetic）启发的进化方法：
- **混合专家 (MoE) 架构**：动态调度不同的LLM执行特定任务（例如：GPT-4.5 负责创意生成，Claude 3.7 负责高保真代码实现，DeepSeek-R1 负责深度逻辑分析和进化交叉操作）。
- **协同搜索**：将 LLM 引导的个体局部微调与全局的进化探索相结合。
- **提示词自优化**：框架会基于历史性能数据，自动分析失败与成功的经验，迭代优化自身的 Prompt（提示词），引导模型避开错误方向。

## AESAT 能用来做什么？

**💖 开发者寄语：**

这个框架大约是在 **2024年底** 完成的。整体的设计架构很大程度上倾向于当时的模型能力——特别是当时模型的“注意力（Context Window/Attention）有限”。因此，在设计之初，我们就让它专精于一种极其专注且硬核的场景。

🎯 **你可以使用它来优化你当前“把握不定”，但是“性能极其关键”的启发式函数，或者其他核心关键代码。**

- **无可匹敌的模块化优化能力**：经过我们的大量实验证明，AESAT 对单一模块化函数的优化效果强得令人难以置信。甚至可以说，**哪怕是与我们目前正在研发的最新的框架相比，AESAT 的单模块优化能力仍然是最强的。** 它可以深入挖掘代码逻辑，常常能发现违背人类直觉但极其高效的算法策略。
- **人类经验的最佳拍档**：如果你在算法设计时，直觉上知道某个模块有优化空间，或者想尝试一种新的评分机制但不知道完美的数学公式该怎么写，把这个模块交给 AESAT 就对了！它会像一个不知疲倦的科研助手，不断生成、测试、反思和进化，直到帮你找到那个最完美的变体。

**关于缺点与未来展望：**
正如它的优点一样，它的缺点也非常明显：**它只能优化单个模块**。因此，它更适合搭配人类的经验，由人来指出“该优化哪里”，由它来负责“重点优化”。
不过请大家期待，我们后续的框架已经改进了这个问题，并正在逐步减少人为因素的干预，走向更全面的自动化。

## 系统要求
- **操作系统**: Linux
- **Python**: 3.8+
- **依赖库**: `ray`, `requests`, `python-dotenv`
- **编译环境**: GCC 编译器 (用于编译 Kissat 源码)

## 项目结构
- `work/data/`: 测试数据目录 (包含 `.cnf` 格式的 SAT 问题实例)。
- `prompt/`: 提示词模板目录 (包含核心代码、生成提示词、全局经验历史等)。
- `originCode/code/`: 原始 Kissat 求解器源码目录。
- `work/results/` & `work/json_results/`: 运行结果与 JSON 格式详细数据目录。
- `replace/`: 代码替换目录 (生成的代码变体文件)。

## 详细执行步骤

### 1. 环境配置
```bash
pip install -r requirements.txt
pip install ray
cd originCode/code && make
```

### 2. 配置 API Keys
编辑 `config.py` 文件，设置你的 OpenAI, Claude 和 DeepSeek 的 API 密钥及模型配置。

> [!TIP]
> **模型配置建议**
> 为了最大化混合专家 (MoE) 架构的优势，我们**强烈建议尽量使用三个不同的模型**分别负责生成、代码实现和分析（正如配置示例中的 GPT-4.5、Claude 3.7 和 DeepSeek-R1）。当然，您完全可以将三个接口都配置为使用同一个模型 API，但这样做优化效果会大打折扣。

### 3. 准备测试数据
请从 `work/data/download.txt` 中获取并下载测试用例数据。

### 4. 运行系统
```bash
python main.py
```
系统将自动初始化 Ray 框架，执行基线测试，生成多种代码变体，并并行执行多轮迭代进化优化。

### 5. 查看结果
运行过程中控制台会输出实时进度。运行结束后，可前往 `work/json_results/{timestamp}/` 目录查看最终的最优解 (`final_best_solution.json`) 以及完整的性能对比演化数据。

## 配置参数说明
可以在 `config.py` 中调整的关键参数：
- `SOLUTION_COUNT`: 初始生成的解决方案数量 (默认 20)。
- `VARIANT_COUNT`: 每个方案生成的变体数量 (默认 3)。
- `DATA_PARALLEL_SIZE`: 数据并行处理大小 (默认 60)。
- `MAX_ITERATIONS`: 每个方案的最大迭代微调次数 (默认 3)。

## 注意事项与常见问题解答
- **极低的运行成本**：单轮优化的 token 成本极低（不到 1 元人民币）。
- **API 调用频率**：尽管成本很低，但进化过程仍会频繁进行 API 调用，建议初期使用小规模测试集进行调试以确保流程顺利。
- **计算资源**: 系统使用 Ray 进行并行评测，请确保有充足的 CPU 和内存资源。
- **执行时间**: 完整的演化运行可能需要数小时，具体取决于数据集大小和 API 响应速度。
